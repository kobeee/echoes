## 一、设计审计：当前原型问题全景

> 以下基于 `echoes.pen` 文件实际截图与节点数据的逐项审查。

### 1.1 结构性问题（阻断级）

| # | 问题 | 当前值 | 正确值 | 严重度 |
|---|------|--------|--------|--------|
| S1 | **可复用组件数为 0** | 所有页面平铺，无共享组件 | 应建立 8-12 个基础组件 | 🔴 Critical |
| S2 | **屏幕尺寸偏差** | 393×852pt | 393×852pt 是正确的（iPhone 15/16 Pro 逻辑分辨率），但设计文档写了 402×874 造成混乱 | 🟡 Medium |
| S3 | **安全区域完全缺失** | 顶部 0pt / 底部 0pt | 顶部 59pt（Dynamic Island）+ 状态栏区域；底部 34pt（Home Indicator） | 🔴 Critical |
| S4 | **Grid 辅助线残留** | 6 条实线 `#1A1A1F`（3 竖 + 3 横） | 应在最终原型中完全移除，或改为 3% opacity 虚线 | 🔴 Critical |

### 1.2 视觉层次问题

| # | 问题 | 当前值 | 建议值 | 严重度 |
|---|------|--------|--------|--------|
| V1 | **背景层级对比度不足** | `#0A0A0F` vs `#1A1A1F`（对比度 1.15:1） | `#000000` vs `#1C1C1E`（对比度 1.45:1） | 🔴 Critical |
| V2 | **金色品牌色在暗底上偏脏** | `#D4AF37` 单一色值通吃所有场景 | 建立 5 级金色色阶，按用途分配 | 🟡 Medium |
| V3 | **字体使用 Inter 而非 SF Pro** | `fontFamily: "Inter"` 全局 | `-apple-system` / SF Pro | 🔴 Critical |
| V4 | **透明度滥用** | 雷达圈 opacity 0.1/0.2/0.3，扫描线 0.5，标题 0.8 | 用实色 + 层级颜色替代，避免叠加透明导致"脏"感 | 🟡 Medium |
| V5 | **Echo 信号点过小且无层次** | 8×8px 实心圆，无光晕 | 12×12pt 核心 + 24pt 辉光 + 48pt 外圈呼吸 | 🟡 Medium |

### 1.3 iOS 规范违规

| # | 问题 | 当前实现 | iOS HIG 要求 | 严重度 |
|---|------|----------|-------------|--------|
| H1 | **图标体系错误** | `Material Symbols Rounded`（home, person, settings, navigation） | SF Symbols 6.0（house, person, gearshape, location.north） | 🔴 Critical |
| H2 | **返回按钮用文字 `<`** | `content: "<"`, Inter 24px | SF Symbols `chevron.left` + 页面标题文字 | 🔴 Critical |
| H3 | **SOS 按钮仅 48×48pt** | 触控热区可能不足 | 最小触控区域 44×44pt（按钮本体），建议 SOS 这类紧急按钮 ≥56pt | 🟡 Medium |
| H4 | **导航栏未使用系统模式** | 自定义 pill 形状，仅 2 个图标 | 应为 5 个 Tab（首页/地图/埋藏/足迹/设置），或 iOS 标准 TabBar | 🟡 Medium |
| H5 | **圆角体系不统一** | navPill 36px / 按钮 22-30px / 卡片 12-16px / SOS 24px | 应建立统一的圆角 Token 体系 | 🟡 Medium |

### 1.4 缺失设计

| # | 缺失内容 | PRD 重要度 | 说明 |
|---|---------|-----------|------|
| M1 | **启动页 (Launch Screen)** | 高 | 品牌第一印象，金色波纹扩散动画 |
| M2 | **Widget 桌面组件** | 🔴 极高 | PRD 明确指出"通过 Widget 完成 80% 交互"，这是产品核心入口 |
| M3 | **Live Activity 灵动岛** | 高 | 寻宝模式的实时距离追踪 |
| M4 | **空状态页** | 中 | 首次打开无数据时的引导 |
| M5 | **加载/骨架屏** | 中 | 数据加载过程的占位 |
| M6 | **录制中状态** | 高 | 埋藏页面的录制进行时视觉反馈 |
| M7 | **权限请求页** | 中 | 位置/麦克风权限的自定义引导页 |

## 二、设计基础：iOS 原生规范体系

### 2.1 屏幕布局模型

```
┌─────────────────────────────────────┐  ← 0pt
│         Status Bar (54pt)           │
│    ┌───────────────────────┐        │
│    │   Dynamic Island      │        │  ← 居中，约 126×37pt
│    └───────────────────────┘        │
├─────────────────────────────────────┤  ← 59pt（Safe Area Top）
│                                     │
│         内容安全区域                 │
│         (Safe Area Content)         │
│                                     │
│    宽度: 393pt                      │
│    可用高度: 852 - 59 - 34 = 759pt  │
│                                     │
├─────────────────────────────────────┤  ← 818pt（Safe Area Bottom）
│      Home Indicator (34pt)          │
└─────────────────────────────────────┘  ← 852pt

屏幕边距:
  标准: 16pt（列表、卡片）
  紧凑: 20pt（大标题文字的左缩进，iOS Large Title 标准）
```

### 2.2 字体规范 (SF Pro)

Apple 对 SF Pro 有严格的**字号-字重映射关系**和**用途语义**：

| 语义名称 | 字号 | 字重 | 字体族 | 行高 | 用途 |
|---------|------|------|--------|------|------|
| **Large Title** | 34pt | Bold (700) | SF Pro Display | 41pt | 页面大标题（我的足迹、设置） |
| **Title 1** | 28pt | Bold (700) | SF Pro Display | 34pt | 章节标题 |
| **Title 2** | 22pt | Bold (700) | SF Pro Display | 28pt | 卡片标题 |
| **Title 3** | 20pt | Semibold (600) | SF Pro Display | 25pt | 子标题 |
| **Headline** | 17pt | Semibold (600) | SF Pro Text | 22pt | 列表项标题 |
| **Body** | 17pt | Regular (400) | SF Pro Text | 22pt | 正文（iOS 默认阅读字号） |
| **Callout** | 16pt | Regular (400) | SF Pro Text | 21pt | 按钮文字 |
| **Subhead** | 15pt | Regular (400) | SF Pro Text | 20pt | 副标题、说明文字 |
| **Footnote** | 13pt | Regular (400) | SF Pro Text | 18pt | 辅助信息、时间戳 |
| **Caption 1** | 12pt | Regular (400) | SF Pro Text | 16pt | TabBar 标签 |
| **Caption 2** | 11pt | Regular (400) | SF Pro Text | 13pt | 微小信息 |

> **关键规则**: 20pt 以上使用 SF Pro Display（字间距更紧凑、更优雅），20pt 以下使用 SF Pro Text（字间距更宽松、更易读）。

### 2.3 色彩规范 (Dark Mode)

#### 系统背景色（三级递进）

| 层级 | 色值 | 用途 | 与上层对比度 |
|------|------|------|-------------|
| **Primary** | `#000000` | 屏幕底层，OLED 像素关闭 | — |
| **Secondary** | `#1C1C1E` | 卡片、分组背景 | 1.45:1 |
| **Tertiary** | `#2C2C2E` | 输入框、按钮底色 | 1.22:1（与 Secondary） |
| **Elevated** | `#1C1C1E` | 模态视图、浮层 | 同 Secondary |

#### 系统文字色

| 层级 | 色值 | 对比度 (vs #000) | 用途 |
|------|------|-----------------|------|
| **Primary** | `#FFFFFF` | 21:1 | 标题、重要信息 |
| **Secondary** | `rgba(235,235,245,0.60)` → 等效 `#98989F` | 6.4:1 | 副标题、说明 |
| **Tertiary** | `rgba(235,235,245,0.30)` → 等效 `#48484A` | 2.8:1 | 占位符、禁用态 |
| **Quaternary** | `rgba(235,235,245,0.18)` → 等效 `#2E2E30` | 1.7:1 | 分隔线 |

> **注意**: iOS 的次要文字使用带蓝紫调的灰色（`#EBEBF5` 基底），而非纯灰。这使得文字在深色背景上更柔和，不会显得"死灰"。

#### 系统分隔线

| 类型 | 色值 | 用途 |
|------|------|------|
| **Opaque** | `#38383A` | 不透明分隔线 |
| **Non-opaque** | `rgba(84,84,88,0.65)` | 列表内部分隔线（半透明） |

### 2.4 间距系统 (8pt Grid)

iOS 的间距基于 **8pt 基准网格**，辅以 4pt 微调：

| Token 名称 | 值 | 典型用途 |
|-----------|-----|---------|
| `space-2` | 2pt | 图标与文字间微距 |
| `space-4` | 4pt | 紧凑元素间距、Badge 内边距 |
| `space-8` | 8pt | 行内元素间距、列表项内小元素间距 |
| `space-12` | 12pt | 列表项内较大元素间距 |
| `space-16` | 16pt | 屏幕边距、卡片内边距、列表项垂直间距 |
| `space-20` | 20pt | 大标题左缩进 |
| `space-24` | 24pt | 区块间距 |
| `space-32` | 32pt | 大区块间距 |
| `space-48` | 48pt | 页面顶部/底部留白 |

### 2.5 圆角系统 (Continuous Corners)

iOS 使用 **Continuous Corner**（连续曲率圆角，又称 Squircle），而非标准 CSS border-radius。差异在弧线过渡更平滑。

| Token 名称 | 值 | 用途 |
|-----------|-----|------|
| `radius-xs` | 6pt | 小标签、Badge |
| `radius-sm` | 10pt | 按钮、输入框、Segmented Control |
| `radius-md` | 12pt | 卡片、列表分组容器 |
| `radius-lg` | 16pt | 大卡片、Bottom Sheet |
| `radius-xl` | 20pt | 模态视图顶部 |
| `radius-2xl` | 22pt | 浮动导航栏 |
| `radius-full` | 9999pt | 胶囊按钮、药丸标签、头像 |

> **嵌套圆角规则**: 内层圆角 = 外层圆角 - 间距。例如外层 16pt 圆角 + 8pt padding → 内层应为 8pt 圆角。

### 2.6 SF Symbols 规范

| 上下文 | 渲染模式 | 权重 | 比例 | 尺寸 |
|--------|---------|------|------|------|
| **NavigationBar** | Monochrome | Regular | — | 22pt (pointSize) |
| **TabBar** | Hierarchical / Palette | Medium | — | 24pt，选中态可用填充变体 |
| **大功能图标** | Multicolor 或 Palette | Light-Regular | Large | 32-48pt |
| **列表行** | Monochrome | Regular | Medium | 20pt |
| **Badge/装饰** | Hierarchical | — | Small | 12-16pt |

**Echoes 中的 SF Symbols 映射：**

| 当前 Material Symbols | → SF Symbols 替换 | 说明 |
|----------------------|------------------|------|
| `home` | `house` / `house.fill` | TabBar 首页 |
| `person` | `person` / `person.fill` | TabBar 个人 |
| `settings` | `gearshape` / `gearshape.fill` | TabBar/足迹页设置 |
| `navigation` | `location.north.fill` | 拾取页方向箭头 |
| `mic` | `mic.fill` | 录制按钮 |
| `add` | `plus` | 中央操作按钮 |
| `map` | `map` / `map.fill` | TabBar 地图 |
| `folder` | `archivebox` / `archivebox.fill` | TabBar 足迹 |

| — (缺失) | `chevron.left` | 返回按钮 |

### 2.7 Widget 设计规范 (WidgetKit)

| 尺寸 | 逻辑宽 × 高 (pt) | 内边距 | 圆角 | 说明 |
|------|-----------------|--------|------|------|
| **Small** | 158 × 158 | 16pt | 22pt | 2×2 图标网格，不支持滚动 |
| **Medium** | 338 × 158 | 16pt | 22pt | 4×2 图标网格 |
| **Large** | 338 × 338 | 16pt | 22pt | 4×4 图标网格 |

**Widget 设计约束：**
- 背景必须不透明（不支持 `clear` 背景）
- 不支持滚动、动画、视频
- 仅支持 `Button` 和 `Toggle` 交互（iOS 17+）
- 点击区域即 Deep Link，每个区域可指向 App 不同页面
- 字号建议 ≥ 13pt（小屏距离阅读）

```
│                                          │

设计规则:
- 背景: 纯黑 #000000（与 Dynamic Island 硬件融合）
```

## 三、设计系统：Token 与组件库

### 3.1 颜色 Token（完整色板）

#### 品牌色 - 金色 (Gold)

金色是 Echoes 的灵魂色，代表"回响"的温暖。不同场景需要不同的金色变体：

| Token | 色值 | 用途 | 对比度 (vs #000) |
|-------|------|------|-----------------|
| `gold-50` | `#D4AA4015` | 辉光/光晕背景层（15% opacity 叠加） | — |
| `gold-100` | `#2A2318` | 金色组件的微弱底色/背景色 | 1.13:1 |
| `gold-200` | `#5C4A24` | 金色元素的暗态/禁用底 | 2.44:1 |
| `gold-300` | `#8C7438` | 次要装饰线、时间线节点 | 3.78:1 |
| `gold-400` | `#B89A4A` | 图标填充、次要按钮边框 | 5.42:1 ✅ AA |
| `gold-500` | `#D4AA40` | **主品牌色**（按钮、录制圆、核心 CTA） | 6.73:1 ✅ AA |
| `gold-600` | `#E0BE5C` | Hover/Pressed 高亮态 | 8.24:1 ✅ AAA |
| `gold-700` | `#EAD07A` | 小字文字标签（在深色背景上） | 10.1:1 ✅ AAA |
| `gold-800` | `#F2E0A0` | 大面积文字（标题级别） | 12.6:1 ✅ AAA |
| `gold-900` | `#F8EFC8` | 最亮级别，仅用于高亮数字/badge | 15.2:1 ✅ AAA |

> 与旧方案对比: 旧方案仅使用 `#D4AF37` 一个色值，在 Dark Mode 中偏"脏黄"。新体系将色相微调偏暖（从 `#D4AF37` 的 Hue 46° 调整为 `#D4AA40` 的 Hue 43°），同时建立完整明度梯度。

#### 功能色 - 信号青 (Teal)

| Token | 色值 | 用途 |
|-------|------|------|
| `teal-50` | `#00BFA515` | 雷达扫描辉光层 |
| `teal-100` | `#0A2622` | 青色元素底色 |
| `teal-300` | `#007A68` | 暗态/远距离信号 |
| `teal-500` | `#00BFA5` | **主功能色**（雷达线、定位点、信号条） |
| `teal-600` | `#00D9BC` | 高亮态 |
| `teal-700` | `#4DE8D0` | 文字标签（小字） |

> 与旧方案对比: 旧 `#00D9C0` 亮度过高，在纯黑背景上刺眼。新 `#00BFA5` 降低了 15% 亮度，同时保持了足够辨识度。

#### 功能色 - 加密紫 (Purple)

| Token | 色值 | 用途 |
|-------|------|------|
| `purple-100` | `#1E1528` | 紫色元素底色 |
| `purple-500` | `#8E6DAF` | 加密 Echo 信号点 |
| `purple-600` | `#A78BC4` | 高亮态 |
| `purple-700` | `#C4ADDB` | 文字标签 |

> 与旧方案对比: 旧 `#9B59B6` 饱和度过高。新 `#8E6DAF` 降饱和 25%，在 Dark Mode 下更舒适。

#### 功能色 - 紧急红 (Red)

| Token | 色值 | 用途 |
|-------|------|------|
| `red-100` | `#2A0F0F` | 黑匣子页面背景（极深红） |
| `red-200` | `#4A1A1A` | 进度条底色 |
| `red-500` | `#FF453A` | **iOS 系统红**（非 #FF3B30，这是 Dark Mode 专用色） |
| `red-600` | `#FF6961` | 高亮/脉冲态 |

> **重要**: iOS Dark Mode 中的系统红是 `#FF453A`，而非 Light Mode 的 `#FF3B30`。Apple 专门为 Dark Mode 调高了亮度以保证可读性。

#### 背景与表面色

| Token | 色值 | 用途 |
|-------|------|------|
| `bg-primary` | `#000000` | 屏幕背景（OLED 像素关闭） |
| `bg-secondary` | `#1C1C1E` | 卡片背景、分组容器 |
| `bg-tertiary` | `#2C2C2E` | 输入框底色、Toggle 底色 |
| `bg-elevated` | `#1C1C1E` | 模态/浮层背景（同 secondary，但语义不同） |
| `bg-grouped` | `#000000` | Grouped Table 外层背景 |
| `surface-blur` | `rgba(28,28,30,0.72)` | 毛玻璃材质层（配合 blur 20pt） |
| `separator` | `#38383A` | 分隔线 |
| `separator-light` | `rgba(84,84,88,0.36)` | 列表内轻分隔线 |

#### 文字色

| Token | 色值 | 用途 |
|-------|------|------|
| `text-primary` | `#FFFFFF` | 标题、关键信息 |
| `text-secondary` | `#98989F` | 副标题、说明文字（等效 `rgba(235,235,245,0.6)`） |
| `text-tertiary` | `#48484A` | 占位符文字、禁用文字 |
| `text-on-gold` | `#1A1400` | 金色按钮上的文字（深褐色，非纯黑） |
| `text-on-red` | `#FFFFFF` | 红色按钮上的文字 |

### 3.2 可复用组件库

当前 `.pen` 文件中可复用组件数为 **0**，这是最大的结构性问题。以下定义 Echoes 需要的完整组件库：

#### 基础组件

```
Component: NavBar (导航栏)
├── 变体 A: 标准导航栏
│   ├── 左侧: chevron.left 图标 (22pt) + 上级页面标题 (17pt Body)
│   ├── 中央: 当前页面标题 (17pt Headline Semibold)
│   └── 右侧: 操作按钮 (可选，最多 2 个)
├── 变体 B: 大标题导航栏
│   ├── 上方: 标准高度 44pt 含小标题
│   └── 下方: Large Title 34pt Bold，左缩进 20pt
├── 尺寸: 宽 393pt × 高 44pt (标准) / 96pt (大标题)
├── 背景: transparent 或 surface-blur（滚动后出现）
└── 底部: separator-light 1px 分隔线（滚动后出现）

Component: TabBar (底部导航)
├── 5 个 Tab: 首页 / 地图 / 埋藏(中央) / 足迹 / 设置
├── 图标: SF Symbols 24pt
│   ├── 未选中: text-secondary + 描边变体
```

| **雷达扫描** | 扇形旋转 | 4000ms/周 | `linear` | 持续旋转 |
| **Echo 脉冲** | 缩放+透明度 | 2000ms/周 | `easeInOut` | scale 1.0→1.5, opacity 10%→0% |
| **录制波形** | 高度变化 | 实时 | `spring(response:0.15)` | 跟随音频振幅 |
| **按钮按下** | 缩放 | 100ms | `easeOut` | scale 1.0→0.97 |
| **按钮释放** | 缩放恢复 | 200ms | `spring(response:0.3)` | scale 0.97→1.0 |
| **数字变化** | 滚动替换 | 300ms | `spring(response:0.3)` | `.contentTransition(.numericText())` |
| **金色呼吸** | 透明度 | 2000ms/周 | `easeInOut` | opacity 5%↔15% |
| **信号发现** | 弹入 | 500ms | `spring(response:0.5, dampingFraction:0.6)` | 新 Echo 出现 |
| **导航栏模糊** | 透明→模糊 | 200ms | `easeOut` | 随滚动触发 |

### 6.2 触觉反馈矩阵

| 事件 | Haptic 类型 | iOS API | 视觉对应 |
|------|------------|---------|---------|
| **埋藏成功** | 轻触 | `UIImpactFeedbackGenerator(.light)` | 金色波纹从按钮扩散至全屏 |
| **发现新 Echo** | 通知成功 | `UINotificationFeedbackGenerator(.success)` | EchoPoint 弹入动画 |
| **进入 5m 范围** | 心跳节奏 | Custom pattern: 0.15s heavy → 0.1s pause → 0.15s medium → 0.6s pause | 全屏金色呼吸光效 |
| **SOS 触发** | 连续强震 | `UIImpactFeedbackGenerator(.heavy)` × 3, 间隔 0.2s | 红色脉冲 + 屏幕边缘闪烁 |
| **解锁内容** | 中度冲击 | `UIImpactFeedbackGenerator(.medium)` | 卡片展开 + 内容淡入 |
| **口令错误** | 通知错误 | `UINotificationFeedbackGenerator(.error)` | 输入框左右抖动 (shake) |
| **Toggle 切换** | 选择变化 | `UISelectionFeedbackGenerator()` | 标准 UISwitch 动画 |
| **滑动删除** | 轻触 | `UIImpactFeedbackGenerator(.light)` | 行向左滑出 + 红色删除按钮露出 |

### 6.3 声音设计建议

| 场景 | 声音特征 | 时长 | 说明 |
|------|---------|------|------|
| **发现 Echo** | 清脆的"叮"声 + 轻微回声尾音 | 0.8s | 呼应"回响"主题 |
| **埋藏成功** | 柔和的低频"嗡"声，像石头入水 | 1.2s | 传达"埋入地下"的意象 |
| **SOS 激活** | 低沉的警报单音 | 0.5s | 紧迫但不惊悚 |
| **进入 5m** | 心跳般的低频脉冲 | 持续 | 与 Haptic 心跳节奏同步 |

## 九、设计原则与决策清单

### 9.1 核心设计原则

1. **黑暗中的温暖 (Warmth in Darkness)**  
   纯黑背景不是为了"酷"，而是为了让金色的"回响"更显珍贵。每一个金色光点都像黑暗中的篝火。

2. **减法设计 (Design by Subtraction)**  
   能用一个元素表达的，不用两个。能用颜色区分的，不加文字。能用动效暗示的，不加图标。

3. **系统一致性 (System Coherence)**  
   Echoes 是 iOS 生态的一部分，不是独立王国。用 SF Symbols，用 SF Pro，用系统级手势和反馈模式。让用户感觉这个 App "就像 iPhone 自带的一样"。

4. **情感共鸣 (Emotional Resonance)**  
   雷达不只是功能 UI，它是"你正在感知这个世界"的隐喻。金色呼吸光效不只是视觉反馈，它是"有人曾在这里留下温度"的暗示。

5. **渐进披露 (Progressive Disclosure)**  
   首次打开只看到最简界面。加密选项折叠起来，时间锁默认关闭，高级功能通过 Pro 引导。不在第一眼吓退用户。

### 9.2 Do's & Don'ts 清单

#### ✅ Do's

| # | 规则 | 原因 |
|---|------|------|
| 1 | 使用 `#000000` 纯黑背景 | OLED 省电 + iOS Dark Mode 标准 + "深邃"品牌调性 |
| 2 | 金色使用多级色阶 | 不同用途需要不同亮度/饱和度 |
| 3 | 所有图标用 SF Symbols 6.0 | 与系统风格统一，支持 Dynamic Type 缩放 |
| 4 | 触控区域 ≥ 44×44pt | iOS HIG 强制要求 |
| 5 | 计时器使用 SF Mono 等宽字体 | 避免数字变化导致的宽度抖动 |
| 6 | 卡片用 Continuous Corner (Squircle) | iOS 标准圆角，比 CSS border-radius 更自然 |
| 7 | 导航栏/TabBar 使用毛玻璃材质 | 系统级效果，增加层次深度 |
| 8 | Echo 信号点使用三层结构（核心+辉光+脉冲） | 传达"有生命力"的感觉 |
| 9 | 文字色使用带蓝紫调的灰 (`#EBEBF5` 基底) | iOS 标准，比纯灰更柔和 |
| 10 | 支持 Dynamic Type 和 VoiceOver | 无障碍是 Apple 审核重点 |

#### ❌ Don'ts

| # | 规则 | 原因 |
|---|------|------|
| 1 | 不要在正式原型中保留 Grid 辅助线 | 破坏沉浸感 |
| 2 | 不要使用 Material Symbols | 与 iOS 系统风格冲突 |
| 3 | 不要用 Inter 字体 | 非 Apple 生态字体 |
| 4 | 不要用纯白 `#FFFFFF` 作为大面积文字色 | 在纯黑背景上过于刺眼 (标题除外) |
| 5 | 不要在 Dark Mode 中使用高饱和度颜色 | Apple 建议降低 20-30% |
| 6 | 不要用 `opacity` 来创建颜色层级 | 会导致叠加时颜色变"脏"，应使用实色 Token |
| 7 | 不要把重要按钮放在屏幕底部边缘 | 与 Home Indicator 手势冲突 |
| 8 | 不要用文字 `<` 作返回按钮 | 必须用 `chevron.left` SF Symbol |
| 9 | 不要让 Dynamic Island 遮挡内容 | 预留 59pt 安全区 |
| 10 | 不要忽略 Reduce Motion 用户 | 需要提供静态替代方案 |
